# vision: extract known branded aliases as ALIAS (primitive + brand)

## the outcome world

### the core idea

the ehmpathy stack models many domain values as **branded primitives** — a uuid, a hash, a price, a timestamp, a serialized payload. structurally each is a `string` (or other primitive) carrying a compile-time brand.

the extractor holds a registry of these known branded aliases. when a property's type name is in the registry, it extracts as `ALIAS` and keeps **both** facts:

- **primitive** — the underlying storage type (`STRING`), so a dao gets a text column
- **name** — the brand (`Uuid`, `IsoPrice`, …), so a dao can emit the branded type and validation

```typescript
// input
interface SeaTurtleTag {
  tagId: Uuid;
}

// output
{
  name: 'tagId',
  type: 'ALIAS',
  of: { name: 'Uuid', primitive: 'STRING' },
  nullable: false,
  required: true,
}
```

names outside the registry keep their current behavior (`Date` → DATE, `Ref` / `Literalize` → REFERENCE, unknown → REFERENCE).

### why keep both (the aha moment)

"a `Uuid` is a `string` at the storage boundary, but downstream still wants to know it was a `Uuid`. so extract the primitive *and* the brand — a string that remembers what it is."

before, a branded alias either broke codegen (`REFERENCE { of: 'Uuid' }` → hunt for a domain object that does not exist) or flattened to a bare `STRING` that forgot its brand. now it lands as `ALIAS` that carries both — text column plus provenance.

### before / after

| field | before | after |
|-------|--------|-------|
| `tagId: Uuid` | `REFERENCE { of: 'Uuid' }` | `ALIAS { of: { name: 'Uuid', primitive: 'STRING' } }` |
| `scuteHash: Hash` | `REFERENCE { of: 'Hash' }` | `ALIAS { of: { name: 'Hash', primitive: 'STRING' } }` |
| `laborCost: IsoPrice` | `REFERENCE { of: 'IsoPrice' }` | `ALIAS { of: { name: 'IsoPrice', primitive: 'STRING' } }` |
| `sightedAt: IsoTimeStamp` | `REFERENCE { of: 'IsoTimeStamp' }` | `ALIAS { of: { name: 'IsoTimeStamp', primitive: 'STRING' } }` |
| `diveDuration: IsoDuration` | `REFERENCE { of: 'IsoDuration' }` | `ALIAS { of: { name: 'IsoDuration', primitive: 'STRING' } }` |
| `telemetry: Serializable` | `REFERENCE { of: 'Serializable' }` | `ALIAS { of: { name: 'Serializable', primitive: 'STRING' } }` |

### the uni-time → iso-time modernization

`iso-time` supersedes the legacy `@ehmpathy/uni-time`. the extractor recognizes the iso-time branded family and no longer recognizes `UniDateTime` / `UniDate`. the one test asset that referenced uni-time moves to iso-time, and the uni-time devDependency is dropped.

## the recognized-alias registry

a single lookup maps each known brand to its primitive:

```ts
const KNOWN_ALIASES: { name: string; primitive: DomainObjectPropertyType }[] = [
  // serde-fns
  { name: 'Serializable',    primitive: DomainObjectPropertyType.STRING },
  // uuid-fns
  { name: 'Uuid',            primitive: DomainObjectPropertyType.STRING },
  // hash-fns
  { name: 'Hash',            primitive: DomainObjectPropertyType.STRING },
  // iso-price (words + human string forms)
  { name: 'IsoPrice',        primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoPriceWords',   primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoPriceHuman',   primitive: DomainObjectPropertyType.STRING },
  // iso-time — stamps
  { name: 'IsoTimeStamp',    primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoDateStamp',    primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoMonthStamp',   primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoYearStamp',    primitive: DomainObjectPropertyType.STRING },
  // iso-time — floats
  { name: 'IsoTimeFloat',    primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoHourFloat',    primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoMinuteFloat',  primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoMonthFloat',   primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoDayFloat',     primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoWeekdayFloat', primitive: DomainObjectPropertyType.STRING },
  // iso-time — durations (words form)
  { name: 'IsoDuration',     primitive: DomainObjectPropertyType.STRING },
  { name: 'IsoDurationWords',primitive: DomainObjectPropertyType.STRING },
];
```

a `TypeReference` whose `typeName.escapedText` matches an entry →
`{ type: ALIAS, of: { name, primitive } }`. every primitive is `STRING` today, but the shape leaves room for future non-string brands (e.g. a branded number). `Date` (→ DATE), `Ref`, and `Literalize` keep their dedicated branches. `UniDateTime` / `UniDate` are removed.

### deliberately out of scope

object-shaped types stay as `REFERENCE` (they model structure, not one branded value):

- `IsoPriceShape` — `{ amount, currency }`
- `IsoTimeStampRange`, `IsoDateStampRange` — `{ since, until }`
- `IsoDurationShape` — structured duration

note: `IsoPrice` and `IsoDuration` are each a union that *includes* an object variant, yet both extract as `ALIAS`(STRING) per wisher call — the stored form is the words string (`'USD 50.37'`, `'PT30M'`); the object variants exist only for in-memory convenience.

## test plan — exhaustive per alias (core requirement)

### coverage intent

this is a **core requirement**, not a nicety:

- **every recognized alias gets its own divergent seaturtle-themed fixture** — one distinct sea-world entity per alias (see the table above). no alias is proven by proxy.
- **each fixture asserts** the field extracts as `{ type: ALIAS, of: { name, primitive: STRING } }`.
- **fully snapshotted** — every extraction result *and* every hydration result is captured in a snapshot, so a reviewer can visually spotcheck each brand + primitive in the PR diff. snapshots pair with explicit assertions (assertions prove behavior; snapshots give observability).

### the flag dimensions (orthogonal)

nullable / required / array flags are handled upstream (`extractPrimaryTypeFromMemberDeclaration`), independent of the alias name. so we prove each *flag combination* works on the ALIAS shape, then rely on the shared code path — but we still exercise them across divergent aliases so no combination is untested:

| dimension | example field | expected |
|-----------|---------------|----------|
| required (plain) | `tagId: Uuid` | ALIAS, required, not nullable |
| optional | `patternHash?: Hash` | ALIAS, not required |
| nullable | `laborCost: IsoPrice \| null` | ALIAS, nullable |
| array | `sightings: IsoTimeStamp[]` | ARRAY of ALIAS |

### verification style

per the `ClaimSearch` precedent (`extractPropertiesFromInterfaceDeclaration.test.ts:202-212`): a `ts.createProgram` over each `.test.assets/*.ts` fixture, find the interface, assert `properties.<field>` matches the expected ALIAS shape, **and snapshot**. every fixture is snapshotted — no alias lands without a captured snapshot.

### hydration coverage

a companion hydrate test proves the ALIAS shape survives `getHydratedDomainObjectMetadatasFromFiles` unchanged (ALIAS is terminal — not a REFERENCE, so hydration passes it through), and is itself **fully snapshotted**.

## mental model

### how users describe it

"the extractor knows the ehmpathy branded types — uuid, hash, price, time, serialized — and records each as an ALIAS that remembers both its storage type and its brand."

### analogies

- a luggage tag: the bag is still a bag (`STRING`), but the tag says whose it is (`Uuid`)
- a nutrition label on a bottle of water: still water, but labeled

### terms

| user term | system term |
|-----------|-------------|
| "branded alias" | `TypeReference` whose `escapedText` matches a `KNOWN_ALIASES` entry |
| "extract both" | `{ type: ALIAS, of: { name, primitive } }` |
| "the brand" | `of.name` |
| "storage type" | `of.primitive` |

## evaluation

### how well does it solve the goals?

| goal | solved? |
|------|---------|
| recognize the branded family (serde/uuid/hash/iso-price/iso-time) | yes |
| keep both the primitive and the brand | yes (`ALIAS` + `of.{name,primitive}`) |
| preserve nullable / required | yes (upstream, unchanged) |
| arrays of aliases (`Uuid[]`) → ARRAY of ALIAS | yes |
| remove uni-time recognition | yes |
| swap uni-time fixture → iso-time, drop devDep | yes |
| keep object-shaped types as REFERENCE | yes |
| **(core)** exhaustive per-alias coverage, divergent seaturtle fixtures | yes (one distinct entity each) |
| **(core)** fully snapshotted (extraction + hydration) | yes |

### pros

- downstream gets a text column **and** the brand — richer codegen (branded dao types, format validation)
- uses the reserved-but-idle `ALIAS` enum value for its evident purpose
- the `of: { name, primitive }` shape already exists — it is exactly what `extractAliasMetadataFromAliasDeclaration` returns
- one registry replaces the per-name `if` branches — one obvious place to extend

### cons

- `ALIAS` is a new output shape every downstream consumer must learn (previously these were STRING or REFERENCE)
- the `of` union on `DomainObjectPropertyMetadata` gains a variant (`{ name, primitive }`) — a contract touch (interface + zod)
- name-based match carries a collision risk: any unrelated type named `Uuid` / `Hash` also becomes ALIAS (same accepted risk `Date` / `Ref` carry)
- four new devDependencies to install and pin

### edgecases & pit of success

| edgecase | behavior | pit of success? |
|----------|----------|-----------------|
| `tagId: Uuid` | → ALIAS(STRING), required | ✅ |
| `patternHash?: Hash` | → ALIAS(STRING), not required | ✅ |
| `laborCost: IsoPrice \| null` | → ALIAS(STRING), nullable | ✅ |
| `sightings: IsoTimeStamp[]` | → ARRAY of ALIAS(STRING) | ✅ (array branch recurses) |
| `diveDuration: IsoDuration` | → ALIAS(STRING) (words form) | ✅ |
| `window: IsoTimeStampRange` | → REFERENCE (object) | ✅ correctly unchanged |
| `shape: IsoPriceShape` | → REFERENCE (object) | ✅ correctly unchanged |
| `d: UniDateTime` | → REFERENCE (recognition removed) | ⚠️ intended — migrate to iso-time |
| `Date` / `Ref` / `Literalize` | unchanged | ✅ |

## open questions & assumptions

### assumptions made

1. **each registry alias is a branded primitive at the storage boundary** [answered by source] — verified each is `AsOfGlossary<string, ...>`, `string & {...}`, or a template-literal string union. `IsoPrice` / `IsoDuration` are unions with an object variant, but the wisher chose their string (words) form.
2. **name-based match is sufficient** [answered by code] — the extractor switches on `typeName.escapedText` only (`extractPropertyDefinitionFromAstNode.ts:106`).
3. **nullable / required handled upstream** [answered by code] — `extractPrimaryTypeFromMemberDeclaration.ts:96`.
4. **`ALIAS` is terminal in hydration** [answered by code] — hydration only re-processes `REFERENCE` (`getHydratedDomainObjectMetadatasFromFiles.ts:55`); an `ALIAS` property passes through unchanged.

### questions

1. **local primitive aliases — unify to ALIAS** [answered, 2026-07-22] — a *local* `type StandardDate = string` used as `onDate: StandardDate` currently hydrates to `{ type: STRING, of: 'StandardDate' }` (snapshot `getHydratedDomainObjectMetadatasFromFiles.test.ts.snap:416-420`). wisher chose to **unify**: local primitive aliases also become `{ type: ALIAS, of: { name, primitive } }`, so all aliased primitives share one shape. this changes the hydrate local-alias path (`getHydratedDomainObjectMetadatasFromFiles.ts:89-93`) to set `type: ALIAS` + `of: { name, primitive }` (instead of `type: primitive`, `of: name`), and updates the `PerformanceReport` snapshot.
2. **`Serializable` fixture source** [answered 2026-06-30, ~~local decl~~ **superseded 2026-07-23**] — ~~declared locally (`type Serializable = ...`); serde-fns not added as a dep.~~ per the wisher's 2026-07-23 override (`0.wish.md` `.decisions`), serde-fns **is** added: `serde-fns@1.3.1` is a real pinned devDependency and the fixture imports the true `Serializable` from it. so **five** real devDependencies, all imported.
3. **flag-combination breadth** [answered] — each alias tested for the plain (required) case; nullable / optional / array proven across a divergent subset (they are alias-orthogonal, shared upstream). refinable at the test-blueprint stone.

## what is awkward?

- **`ALIAS` is a contract expansion, not just a value fix.** it adds a new `of` variant and a new output shape consumers must handle. that is the cost of "extract both" — richer than a bare STRING, heavier than a plain fix. justified by the downstream value (branded columns, validation).
- **one shape for aliased primitives (registry + local).** both registry aliases (extract step) and local primitive aliases (hydrate step) now emit `{ type: ALIAS, of: { name, primitive } }`. this is a behavior change to the extant local-alias output (`PerformanceReport.onDate` snapshot updates), but it removes the two-shapes-for-one-concept awkwardness.
- **curated registry vs plugins.** `KNOWN_ALIASES` is a larger, more honest form of the extant hardcoded aliases, yet still a hardcoded list — it nudges the code's own `todo: support future aliases via plugins` debt. right move now; plugin system stays out of scope.
- **name-collision blast radius.** each registry entry means any unrelated type of that name becomes ALIAS. low risk for `IsoTimeStamp`, slightly higher for a common word like `Hash`. accepted, consistent with the `Date`/`Ref` precedent, disclosed.
- **uni-time removal is a break-change.** a consumer still annotating with `UniDateTime` regresses to REFERENCE. intended, worth a changelog callout.
