## peer-review blocker addressed (r011: enroll-impl-arch-defects)

peer review flagged a real gap my vision missed: a template literal unioned with a string literal
(e.g. `` `v${number}` | 'latest' ``) threw `BadRequestError` instead of collapse to STRING —
inconsistent with both the #17 string-literal-union collapse and this fix's own promise. root cause:
the union-homogeneity check gated on `kind === LiteralType`, which a `TemplateLiteralType` (203) fails.

**structural fix (solve-at-cause + consistent-mechanisms):** unified on the single primitive
extractor. replaced the two duplicated `allAreLiteralType` gates with one call to a renamed resolver
that maps each subtype through `extractPrimitiveTypeFromAstNodeDeclaration` (the sole source of truth
for kind→primitive, which already handles LiteralType, keyword, and now template-literal kinds).

5. `src/domain.operations/extract/extractHomogeneousUnionPrimitiveType.ts` (new, replaces
   `extractHomogeneousLiteralUnionType.ts`)
   - maps each union subtype via `extractPrimitiveTypeFromAstNodeDeclaration`; returns the primitive
     iff all subtypes map to the same non-null primitive.
   - behavior stays identical for all prior literal-union cases (traced + verified by green suite).

6. `extractPrimaryTypeFromMemberDeclaration.ts` + `extractPropertyDefinitionFromAstNode.ts`
   - swapped the duplicated `allAreLiteralType` gate for a single `extractHomogeneousUnionPrimitiveType` call.
   - de-duplicates the collapse logic (was 2 copies) → one resolver.

7. new regression assets + tests:
   - `TemplateLiteralUnion.ts`: `` `v${number}` | 'latest' `` → STRING; `` ... | null `` → STRING nullable; `` `v${number}`[] `` → ARRAY of STRING.
   - `MixedTemplateUnion.ts`: `` `v${number}` | number `` → throws BadRequestError.

verified: types 🎉, full unit suite 34 passed / 0 failed / 0 skipped, format 🎉.
