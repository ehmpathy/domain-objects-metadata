# wish: support template literal types as string

## .what

template literal types (`TypeKind 203`) are not yet supported. treat them as `string` for schema generation.

```ts
version: `v${number}.${number}.${number}`;
```

current error:
```
UnexpectedCodePathError: could not extract property definition from interface member declaration
{ "propertyName": "version", "primaryTypeKind": 203 }
```

## .source

full spec lives in the github issue (handoffs-at-source):
- ehmpathy/domain-objects-metadata#21
- read it: `gh issue view 21 --repo ehmpathy/domain-objects-metadata`

## .acceptance

- test asset with a template-literal-typed prop
- extracts as `string`, nullable/required preserved
