## discovered vision inaccuracies (two edgecases are NOT supported today)

two edgecases the vision's table claimed as working do NOT extract/hydrate today, verified
empirically during execution. fixing them is a change to extraction/hydration — **out of scope**
for this classification wish (which does not touch extraction). flagged for the wisher:

- **`(string | null)[]`** — an element-level union inside an array. extraction throws
  `UnexpectedCodePathError` (`extractPropertyDefinitionFromAstNode`, `primaryTypeKind: 192`).
  the vision conflated this with the outer-level `string[] | null` (which does work); an
  element-level union is a different, unsupported shape.
- **`Variant[]` where `type Variant = 'A' | 'B'`** — a named string-literal-union alias in an
  array. hydration throws `could not hydrate a property who references another type … see
  PrimitiveArrays.variants: Variant` — the alias is treated as a reference to a type that is
  neither a domain object nor an enum, so it is not collapsed to STRING as the vision claimed.

both are prior extraction/hydration limitations, unrelated to the guard classification this
wish delivers. the guards classify correctly whatever the extractor yields.
